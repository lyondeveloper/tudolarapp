# TUDOLAR mobile client

The React Native + Expo client for TUDOLAR, a P2P marketplace for arranging in-person cash and
currency exchanges. Product context lives in the [root README](../../README.md); diagrams are in
[`docs/`](../../docs/).

## Status

The app implements the **Civic Trust Exchange** Stitch interface (`T15`) across authentication,
marketplace discovery, deterministic search, offer details with in-person safety handshake,
contextual P2P chat, post-exchange confirmation, and offer publication preview:

- **Live API state (`src/services/api.ts`)**: `POST /auth/sessions` (sign-in),
  `POST /auth/sessions/refresh`, and `GET /users/me` on the authenticated home screen.
- **Typed preview dataset (`src/features/marketplace/domain/`)**: Local Ciudad Ojeda marketplace
  offers, safe meeting corridors, and agreement conversation state for endpoints scheduled in
  `T04`–`T14`. See [`docs/design/stitch-mobile-mapping.md`](../../docs/design/stitch-mobile-mapping.md)
  for the screen-by-screen Stitch mapping and ADR adaptations.

Not wired to live backend endpoints yet: registration submission (`T02`), passkey ceremony (`T03`),
market selection persistence (`T05`), live offer CRUD (`T07`–`T09`), spatial/manual search API
(`T10`), real-time chat & exchange agreements (`T12`), and incident moderation (`T14`).

## Requirements

- Node.js 24 and npm.
- The API running locally (see [`apps/api/README.md`](../api/README.md)); it listens on port 3000.
- For a device or simulator build: Xcode for iOS, Android Studio for Android.

## Running

```bash
npm install
npm run ios      # or: npm run android
```

`npm run ios` performs a native build (`expo run:ios`), which needs Xcode and CocoaPods. The
`ios/` and `android/` directories are generated by Continuous Native Generation and are not
tracked; configure native behaviour in `app.json`, never by hand.

The client reads its API base URL from `app.json` → `expo.extra.apiBaseUrl`, defaulting to
`http://localhost:3000`. `localhost` only reaches the host from a simulator; a physical device
needs the host's LAN address.

## Design system

The client renders from the approved **Civic Trust Exchange** design system (the Stitch project
"TUDOLAR P2P Marketplace Prototype"). Two files carry it, and there is no `tailwind.config.*` or
nativewind config:

- **[`src/global.css`](src/global.css) — colour, radius, and spacing.** It declares the tokens as
  CSS variables and maps them to Tailwind utilities. Values are space-separated RGB triplets, not
  hex, because the mappings consume them as `rgb(var(--token))`.
- **[`src/theme/typography.ts`](src/theme/typography.ts) — the type scale.** Sizes, line heights,
  weights, and the families loaded through `expo-font`.

Consume a role by naming it as a class, never by writing a value:

```tsx
<Box className="flex-1 bg-background">
  <Text className="text-foreground" style={textStyle('body-lg')}>
    {user.displayName}
  </Text>
  <Text className="text-muted-foreground" style={textStyle('body-md')}>
    {identity}
  </Text>
</Box>
```

Roles in use: `primary` / `primary-foreground` for actions, `secondary` and `success` for
affirmative states, `warning` / `warning-border` / `warning-foreground` for non-custody and safety
notices, `background` / `surface` / `surface-muted` for surfaces, `outline` and `outline-variant`
for borders, and `foreground` / `muted-foreground` for text.

Light is the default presentation. The `@variant dark` block is a seam: it keeps the dark
presentation rendering, but no dark palette has been authored. See [`AGENTS.md`](AGENTS.md) for the
rules that keep the layer coherent.

## Checks

```bash
npm test             # jest-expo + @testing-library/react-native
npx tsc --noEmit     # typecheck
npx expo lint        # lint
```

Run all three before declaring a task done. See [`AGENTS.md`](AGENTS.md) for the commands, the
Expo-version caveats, and the `@react-native/jest-preset` version pin.

Jest stubs stylesheets, so a class name does not resolve to a style in a test. Assert at the token
source — [`src/theme/design-tokens.spec.ts`](src/theme/design-tokens.spec.ts) reads `global.css`
and checks the approved values — or on the roles a screen names, never on resolved colours.

## Structure

```
src/
  app/
    sign-in.tsx                 Stitch 4.2 — sign-in + passkey entry + register link
    register.tsx                Stitch 4.1 — community registration + Pacto de Confianza Ojeda
    home.tsx                    Stitch 1.1 & 1.2 — Ciudad Ojeda discovery + list/map toggle
    search.tsx                  Stitch 1.3 — deterministic manual search (ADR-0015)
    offers/[id].tsx             Stitch 2.1 — offer detail + SafetyHandshakeModal
    publish.tsx                 Stitch 2.2 — publish offer wizard + pilot entitlement (ADR-0014)
    chat/[id].tsx               Stitch 3.1 — contextual P2P chat + safe meeting point picker
    agreements/[id]/confirm.tsx Stitch 3.2 — post-exchange confirmation (ADR-0013)
  __tests__/                    shell and screen specs
  components/ui/                gluestack-ui components
  features/
    auth/                       sign-in and registration forms & hooks
    marketplace/
      domain/                   canonical MVP pairs (ADR-0009), pure calculations, preview dataset
      components/               CivicNoticeBanner, MarketNodeBanner, OfferCard, BottomDock, SafetyHandshakeModal
    session/                    session slice, SecureStore hydration, route gates
  services/                     the single RTK Query API slice
  store/                        Redux store, typed hooks, connectivity wiring
  theme/                        the typographic scale and its contract test
  test-support/                 helpers shared by specs
  global.css                    colour, radius, and spacing tokens
```

Tests must not live under `src/app`: expo-router registers every file there as a route.
